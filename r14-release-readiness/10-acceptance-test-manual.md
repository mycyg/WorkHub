# WorkHub 全量验收测试手册

> 版本基线：main=41a221dd（2026-07-14，R14 九批全部合入）
> 读者：测试同学。按本手册逐条执行，把结果写进文末的「测试报告模板」交回即可，修复由开发跟进。
> 优先级：**P0=必测**（金链路与今天新上的功能）；P1=全面轮测；P2=有时间再抽。
> 图例：每条用例格式为「前置 → 步骤 → 预期」。发现任何与预期不符、或让你困惑超过 10 秒的交互，都算问题，记下来。

## 0. 测试环境准备

### 0.1 服务启动（自托管三步走，详见根目录 README 与 DEPLOY.md）

1. 数据库：`docker compose up -d`（PG 5432 + Redis；容器名 workhub-postgres-1）。
2. 迁移：`DATABASE_URL=postgres://workhub:workhub@127.0.0.1:5432/workhub pnpm --filter @workhub/db migrate`（迁移链应到 0060）。
3. API：`pnpm --filter @workhub/api dev`（8787）。**分两种模式各测一轮**：
   - 有 key 模式：env 带 `LLM_API_KEY`/`LLM_BASE_URL`/`LLM_MODEL`（问开发要测试 key）——AI 链路全量可测。
   - 无 key 模式：不带 LLM 环境变量——专测 §12「无 key 自托管体验」。
4. Web：`pnpm --filter @workhub/web dev`（5173，/api 自动代理到 8787）。
5. 桌面：**必须 `cargo tauri build`** 出正式包（产物在 `client-tauri/src-tauri/target/release/bundle/macos/`），**不要**用裸 `cargo build` 的二进制（会指向开发端口，白屏）。装 .app 后首启会要求输入昵称完成绑定。

### 0.2 测试账号

- 登录是**昵称即登录**（局域网信任模式，无密码）：输入任意昵称即建号。
- 管理员：登录页展开「我是管理员」，口令问开发（env `ADMIN_CLAIM_SECRET`）。
- **协作类用例需要双账号**：开两个浏览器 profile（或一 web 一桌面）分别登录「测试甲」「测试乙」。已有历史数据的账号：验收甲 / 验收乙（WorkHub Demo 项目里有演示消息）。

### 0.3 本轮明确不在测试范围

agent 本地执行/装依赖（EXEC 批未施工）、新手导览（ONBOARD 未做）、移动端（未做）、多副本部署（单实例假设，DEPLOY.md §7）。

## 2. Web 端逐路由巡检（P1，每页 5 分钟）

对以下每个路由做四件事：①空态是否有人话引导（不是裸屏）②有数据时字段真实（时间/计数/人名不是占位）③页内每个按钮都点一遍（不许有点了没反应的假按钮）④窗口缩窄到手机宽度无横向溢出。

路由清单：`/`（首页）、`/projects`、项目主页、`/intake`（新建请求）、`/approvals`（审批工作台）、工单详情、提案详情、`/drive`、`/meetings`、`/inbox`（通知）、`/calendar`、`/health`、replay（run 回放）、`/cost`、`/agents`（军团）、`/knowledge`、`/dashboard/search`、`/dashboard/skills`、`/settings`、`/settings/memory`。

**历史功能回归重点（P1）**：
- 审批工作台：批准/打回（打回必填理由）/委派（选人器）/评论流/批量操作；处理后列表计数与首页计数一致。
- 提案详情：diff 展示、通过/打回/合入、冲突提示、行级编辑器在 SSE 刷新时不丢正在编辑的内容。
- 网盘：上传/重命名/回收站还原/版本历史/「找回这个版本」（应追加新版本而不是抹历史）/文件评论转草稿。
- 会议：上传纪要→洞察→转草稿链路。
- 通知：已读/全部已读/忽略/完成语义区分；通知类型静音设置生效；关联会话的通知有「打开后可见上下文」说明。
- 成本：按人/按执行者分账数字与 run 实际消耗对得上。

## 6. AI 金链路（P0，有 key 模式，成本约 ¥0.1/轮）

**完整走一遍：建项目→群聊讨论→Cuu 拎活→行动卡→审批→回流。**

| # | 用例 | 步骤 → 预期 |
|---|---|---|
| 6.1 | 观察者拎活 | 主区两人讨论一件具体的活（例：「第三节要按新口径重写，用网盘里的周报数据」）→等约 1 分钟→Cuu 发行动卡，条目带置信度与按钮 |
| 6.2 | 行动卡决策 | 执行类条目：批准→军团开工（右栏军团区出现 run，阶段流进度）；撤销窗口内点撤销→置灰划线「已撤销」；改派→选人器换人 |
| 6.3 | @Cuu 直通 | 群里 @Cuu 提问→**秒级**开始回复（不等轮询），流式打字机效果，一轮只回一次不重复 |
| 6.4 | 协同会话 turn | 与 Cuu 的协同会话里直接发文本（不用 @）→Cuu 必回；连发两条→第二条排队不丢；Cuu 忙时提示温和 |
| 6.5 | 回话判定 | 主区闲聊（「中午吃什么」）→Cuu **不**插嘴；提到阻塞/风险/分歧→Cuu 以 PM 口吻介入 |
| 6.6 | 产出与审批（新） | run 跑完→群聊出现产出卡（+N -M）→**点「看提议」→右栏内联打开提议详情**→看 diff 摘要→点「通过」或「打回」（打回必填理由）→**群聊出现落定行**，产出卡状态变化，军团面板同步刷新 |
| 6.7 | 审批异常路径 | 非参与者/无权限账号操作→403 温和话术；重复合入→409 引导去审批工作台 |
| 6.8 | 升级给人 | 造一个需要拍板的决策类条目→@负责人进决策队列（web /approvals 或首页 attention 可见）→处理后群聊/工单状态回流 |

## 11. 安全与权限抽查（P0）

- 非项目 owner 改治理/风险/GitHub 设置→403；直接拼 URL 访问他人私有会话→404（不暴露存在性）。
- web 全站文案**不出现「Cuu」字样**（应叫「AI 助手」）；桌面端才有 Cuu 人设。
- 全站（除聊天 reaction 的五个表情）**无 emoji**；图标全是 SVG/字符。
- 已删除消息的内容在：搜索/引用预览/turn 上下文/导出面 全部不可见。

## 12. 无 key 自托管体验（P1，无 key 模式跑一轮）

- composer 顶部出现「AI 服务未配置」横幅，链到部署文档；@Cuu / 协同发消息→人话报错不白屏；观察者/判定器不启动但**风险巡检照常工作**（它不用 LLM）；`/api/health` 的 `ai_provider_configured=false`。

## 13. 双端一致性抽查（P1）

同一账号同时开 web+桌面：改头像/改资料/处理审批/发消息/读游标——两端各自刷新后状态一致；桌面做的事 web 计数跟上（通知/审批数）。
