# 路由层「事项 / 工单」收口成「任务」，桌面端 MCP 分区消费 last_error_code（工包 F3）

- Status: implemented
- Date: 2026-09-06
- Owner: claude-code

## Problem

M8 的 Note 结尾留了两条互不相干、却都卡在「没人接手」的事：

1. **路由层还在说「事项」**。M8 把五个 service 的用词按 glossary §11 收口成了「任务」，但
   `apps/api/src/routes/` 里同一批话还有 21 处没动——HTTP 错误消息也是用户看得见的文案
   （前端把 `error.message` 直接渲出来）。于是同一个 404 从服务层出来说「任务」、从路由层出来
   说「事项」，取决于请求打在哪条路径上。
2. **桌面端拿到了码却不用**。M7 的 Note 明写「握手超时那句人话给不出」——`describeMcpSessionFailure()`
   在 M3 就把八条会话失败原因翻成了稳定码，只是没有字段带出来。M8 给三个读形状都加了
   `last_error_code`，网页只读清单当天就按码出话了，桌面端仍然只会说「连不上 +（英文诊断）」。
   同一份 Note 还留了第二条：M7 的管理员门是**借**来的（`vm.plugins !== undefined`），M8 之后
   `vm.mcp_servers` 已经存在。

## Decision

### 一、改词之前先把整句搬进词典，一句都不就地改

门禁按「文件 + 归一化片段」记棘轮（`scripts/dev/check-ui-i18n.ts`），就地改一句话会同时产生
「基线条目已消失」与「新增违规」——净效果是门禁变红而账没清。所以 21 处**每一处**都先搬进
`apps/api/src/services/locales.ts`（M8 建的那份），调用点改成 `serviceT(...)`，再改词。
基线只减：2795 → 2768（净减 27，零新增；片段计数 > 站点数是因为同一句话在同一文件里出现多次）。

**词典从「服务层的」变成「API 层的」**。routes 与 services 各写一份等价词典是第二份会漂移的表：
「没有找到这个任务。」这一句在 routes 里出现 6 次、在 services 里已经有一条 `taskNotFound`。
让 routes `import { serviceT } from "../services/locales.js"`，一句话只有一个出处。
文件头注释随之改写；没有新起 `routes/locales.ts`。

**locale 一律传 `"zh-CN"`，只有原本就双语的那一处例外**。这一批是「改词」，不是「把 locale
一路传下去」——后者会改变 en-US 客户端拿到的响应，值得单独一批。唯一的例外是 `pages.ts` 里
「待审批的任务比这里显示的更多」：它本来就是 `locale === "en-US" ? … : …` 的行内三目，
搬进词典后写成 `serviceT(locale, …)` 才是**保持**原行为。

**顺带统一三处不一致**（都是这批已经动到的句子，不额外扩面）：

- 权限类消息此前有「你没有权限修改这个事项。」与「没有权限修改这个事项。」两种写法，一律收成
  带「你」的那种——同一件事在同一个产品里只该有一种口吻。
- 三处 404 的中文消息尾巴上挂着 `(Work item not found.)`。中文消息里夹半句英文本身就是这批要清的
  东西，而且 "work item" 正是 glossary 里那个要退役的英文词；词典的英文侧（`taskNotFound` →
  "That task wasn't found."）已经覆盖 en-US，这条尾巴没有存在的理由。全仓没有任何断言依赖它。
- `proposalActionCopy` 里那条英文原本写着 "the auditable work-item flow"，一并改成 "task flow"。

### 二、桌面端按码出话：一张全表覆盖的映射，而不是一串 case

`MCP_ERROR_CODE_COPY` 是 `Record<McpServerErrorCode, SpotlightViewsCopyKey>` 并带 `satisfies`——
契约里新增第十条码时**这里编译不过**，而不是悄悄落到兜底句上。这比 `switch` 加 `default` 强的
地方正在于此：`default` 会把一条新码渲成一句错话，而且不会有人发现。

**九条码各一句**，且与网页只读清单（`route-components-copy.ts` 的 `settings.mcpErr*`）逐字同句：
同一台服务器在两端只有一种说法，运维把网页上看到的那句话念给桌面端的人听时不会对不上。
第九条 `mcp_connect_failed` 是「这次说不出原因」的兜底码，它的那一句就是既有的通用句
`mcpConnectFailedHint`——不为一个明说了「不知道」的码编一个更具体的原因。测试里有一条断言
「兜底码的那一行」与「根本没有码的那一行」逐字相同。

**连接快照上的码优先于行上的码**：前者来自这个进程最近一次握手，后者是上一次持久化下来的分类。
**码可能缺席**（重启之后这个进程不记得那次失败，M8 的契约注释把这条写死了），那时仍说通用的
那一句，而不是编一个它并不知道的原因。

**重连预算耗尽时两句话都说**：为什么失败（码）+ 为什么不再自动重试。M7 那版是后者顶掉前者——
在只有通用句可说时那是对的（"连不上这台服务器。" 没有信息量），有了码之后就不对了：
「这台服务器没能启动。」和「接连失败太多次，先不自动重连了。」是两件事，下一步动作也不同
（修服务器 vs 点「测试连接」）。中文两句直接相接（句子自带句号），英文之间补一个空格——
与 `withErrorDetail` 里按语言分叉的既有口径一致。

### 三、管理员门换成 `vm.mcp_servers !== undefined`

渲染与拉清单两处一起换。差别不是学术的：M7 借 `vm.plugins` 时，一个「有插件管理权、没有 MCP
管理权」的身份会看到一个必然 403 的分区。当前服务端不存在这种身份，但门的语义应当指向它真正
守的那件事。新增一条测试专钉这个差别：一个填了 `plugins`、没有 `mcp_servers` 的 VM，
MCP 区不渲、清单一次都不拉，而插件区照渲。

## Alternatives considered

- **给路由层新起一份 `routes/locales.ts`**（工位说明里给的另一个选项）。否决：那会让
  「没有找到这个任务。」在两份词典里各存一遍，正是这批要消灭的东西。routes 本来就大量 import
  services，多这一个 import 没有分层代价。
- **把 `proposalActionCopy` 整张表搬进一个 `-copy.ts`**（它形状上本来就是词典）。否决：那会把
  三十来条英文一次性拉进禁词门的英文表扫描面（`BANNED_EN` 只跑词典文件），风险与这批要办的事
  无关。只把改到的那一条挪进词典、其余留在原处，是最小且可解释的做法。
- **在 routes 里改用 `serviceT(requestLocale(c), …)`**。否决：会改变 en-US 客户端拿到的错误消息，
  超出「改词」的范围；`pages.ts` 那一处是因为**原本就**双语才用 locale。
- **就地改词、把棘轮基线里的条目一并改名**。否决：那不叫「基线只减」，只是把同一笔账换个写法记着。
- **桌面端用 `switch (code)` + `default` 出话**（网页那侧的写法）。否决：见上；网页那侧的
  `default` 返回空串、不出这一行，代价小得多，桌面端这里要拿它当唯一的产品句子。
- **码缺席时按 `last_error` 的英文文本猜一个原因**。否决：那串是给人看的现场信息（stderr 尾巴、
  命令路径、失败次数），照着它切字符串会在下一次改措辞时把中文界面变成半截英文——这正是
  M3 起就写在契约注释里的纪律。
- **重连预算耗尽时只说码那一句**（把 M7 的那句顶掉）。否决：用户会看不出「为什么点了没反应」，
  而那句话里恰好带着唯一的出路（点「测试连接」）。

## Consequences

- **改了三条消息的字面，不只是术语**：三处 404 去掉了 `(Work item not found.)` 尾巴；
  四处「没有权限修改这个事项。」补上了「你」；一处英文 "work-item flow" → "task flow"。
  全仓没有断言依赖这三处（唯一一条断言产线消息的 `agent-runs.test.ts` 已同步）。
- **`services/locales.ts` 里 `taskCommentsNotFound` 与 `taskNotFound` 现在只差一条英文尾巴**。
  前者的唯一调用点在 `work-item-comments.ts`（不在本工位的允许改动范围），合并成一条留给下一批。
- **「事项 / 工单」没有门禁**。`check-copy-terms.ts` 的禁词表里没有这两个词，所以这次收口全靠
  人扫一遍 grep，明天就可能被一句新代码带回来。把它们加进禁词表会一次性暴露 60 余处存量
  （`packages/agent` 的提示词、`packages/cuu`、`apps/web` 等），那是一批独立的账，不在这里开。
- **`packages/agent` 的「工单」一个字没动**：那是模型可见文本，与 golden 基线绑在一起，
  按工位纪律与 golden 一起走。`routes/drive.ts` 与 `routes/meetings.ts` 各有一处
  `requireUuidParam(…, "事项")` 也没动——两个文件不在本工位的允许改动清单里。
- **模型可见文本零变化**：`pnpm gen:expected` 两次运行都无 diff。
- **棘轮基线只减**：ui-i18n 2795 → 2768（净减 27，零新增）；禁词基线 49 条不变。
- **桌面端真机未验**（浏览器预览没有 Tauri 运行时，`desktop-webview` 渲染不出）：一台真的连不上
  的服务器，行内那句「原因 + 重连预算 +（诊断）」在窄栏里会比 M7 那版更长，换行值得在 `.app`
  上看一眼。
