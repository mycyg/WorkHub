### 2. [security] Command allowlist bypass: argv[0] basename-normalized for the check but spawned verbatim, so attacker-written ./python runs arbitrary code
- **位置**: `packages/tools/src/sandbox.ts:22-38,111`  ·  区域: tools-lib
- **问题**: ensureCommandAllowed validates normalizeCommandName(args[0]) = path.basename(args[0]).toLowerCase() (lines 22-25,35), but nodeCommandRunner spawns args[0] verbatim: spawn(args[0] as string, ...) with cwd inside the sandbox (line 111, shell:false). The directory part is stripped only for the allowlist check, not for execution. I confirmed end-to-end: wrote an executable file named `python` into the sandbox, then runSandboxedCommand({args:['./python'], cwd:'.', workdir}) ran it -> stdout 'ARBITRARY CODE EXECUTED as fake python' + `id` output, exitCode 0. Equally `['evil/node']`, `['../python']`, `['/usr/bin/python']` all pass ensureCommandAllowed. The LLM controls args (untrusted, file-tools.ts:262-277) and can write_file the fake binary first, so the allowlist guaranteeing 'only trusted interpreters run' is fully defeated (e.g. ship a static curl/nc named `node` for exfil/SSRF).

### 8. [data-flow] applyMergeProposalCandidate bypasses the project advisory lock and stale-base recheck that protect against lost updates
- **位置**: `packages/db/src/repositories/proposals.ts:2050-2138`  ·  区域: db-schema
- **问题**: The normal merge() path (line 2291) serializes same-project adoptions with `pg_advisory_xact_lock(hashtext('project-merge:'+projectId))` and, before superseding, re-checks that exactly one current row was superseded, aborting on zero (lines 2461-2479: `if (superseded.length === 0) throw ... P-COLLAB stale-base abort`). The AI-fusion apply path does NOT take any advisory lock and supersedes the current accepted row with a plain UPDATE that does not assert a row was actually superseded (lines 2127-2138): it reads `readCurrentAccepted` (line 2050), then `if (current) { tx.update(acceptedDeliverableChanges).set({supersededAt}).where(projectId/workItemId + targetKey + supersededAt IS NULL) }` with no `sha256After` guard and no zero-row abort, then inserts a new accepted row with `acceptedVersion = (current?.acceptedVersion ?? 0) + 1`. - **修复**: Push the category predicate into the WHERE clause before limiting, e.g. add `...(options.categories?.length ? [inArray(userMemories.category, options.categories)] : [])` to `conditions`, then drop the post-query JS filter.

### 87. [interaction] Live runtime ignores later events' type/key while a refresh is debounced
- **位置**: `packages/web-runtime/src/live-runtime.ts:171`  ·  区域: dataflow-e2e
- **问题**: `scheduleLiveRouteRefresh` returns early when a timer is already pending (`if (liveRefreshTimer !== undefined) return;`) without updating which `eventType`/`targetKey` will be passed to `onRefresh`/`onRefreshNotice`. If two different events (e.g. a proposalReviewed for the open work item and a notificationCreated) arrive within the 220ms debounce window, the refresh and the user-facing notice (browser.ts:961-962 sseDirtyGuardNotice/sseRefreshNotice) reference only the FIRST event, so the toast can describe the wrong change. The full-route re-fetch keeps data correct, so this is cosmetic, but the notice can mislead.
- **修复**: Capture the latest event into a `pendingEvent = {eventType, targetKey}` variable on every call and read it inside the timer callback, rather than closing over the first event's args.
