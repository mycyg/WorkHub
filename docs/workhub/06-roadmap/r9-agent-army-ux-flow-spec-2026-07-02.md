## 0. 织入哲学（三条铁则，防止军团变成「第二个产品」）

1. **不加新模式、不加新开关。** 用户永远不需要「切换到军团模式」。军团 = intake 之后系统对复杂意图的自然反应：意图简单 → 一条 run（现状不变）；意图复杂 → 多一张「计划提议」卡等你点头。用户的心智模型只增加一句话：「**大活儿，AI 会先给我一份分工计划**」。
2. **人指挥的地方永远是决策收件箱（home）。** dashboard（R9.6）只是观测台——所有需要人拍板的事（批计划/升级/预算/记忆冲突）必须以收件箱卡片出现，人不看 dashboard 也不会漏掉任何决策。这是对既有「决策收件箱首页」（R6-W1）设计的延伸而非替代。
3. **产出管线一寸不改。** 子 agent 的产出依然走 提议→审批→合并→网盘/战绩 的既有管线；军团只是让「提议的生产端」变成多路并行。审批工作台、drive、replay、成本页看到的是**更多同类实体**，不是新实体。

## 1. 端到端用户旅程

### 1.1 金路径（复杂意图 → 军团交付）

| 步 | 用户在哪 | 看到什么 | 可以做什么 | 背后（工程图对应） |
|---|---|---|---|---|
| 1 | web `/intake` 或桌面 Spotlight | 照旧：意图输入 + AI 澄清反问（现有流程，零改动） | 回答澄清 | 现有 clarification |
| 2 | 同上 | 澄清完成后，若 planner 判定为复杂意图（≥2 个可并行子任务），提示条：「这个活儿比较大，Cuu 正在拟一份分工计划…」；简单意图则完全走现状（无感） | 等待（<30s，有骨架态） | R9.1 meta-planner 触发阈值 |
| 3 | 决策收件箱 home | 新卡 **`plan_review`**：标题=「《短剧选题调研》的分工计划等你过目」，摘要=「拆成 4 个子任务 · 预计 ¥0.8 · 2 个并行」，动作=[查看并批准]（primary）[直接改计划][先不拆，单个 AI 跑] | 三选一 | plan 落 proposals，kind 走 `proposal_review`（复用）或新增 `plan_review`（见 §3.3） |
| 4 | 审批工作台 `/approvals`（复用三栏 diff 工作台） | 左栏=计划提议；中栏=**子任务清单 diff 视图**（每行：序号/角色徽章/标题/验收/预算份额/依赖）；右栏=决策面板，主按钮「**批准并派发**」，次按钮「批准但先不跑」「打回重拆（要理由）」 | 行内编辑子任务（复用 R4.22 结构化编辑器：改标题/验收/删行/调预算份额），编辑即成为提议修订 | R9.1 切片 1.3 |
| 5 | 工作项详情 `/workitems/:id` | 新增**「军团」面板**（详设 §3.1）：子任务行 + 状态点 + 成本燃烧条；页面顶部状态徽章从「AI 处理中」细化为「军团推进中 2/4」 | 点子任务行看该 run 的 trace/replay（复用现有 replay 路由）；随时「暂停派发」 | R9.2 |
| 6 | 决策收件箱 | 子任务产出陆续到达：照旧的 `proposal_review` 卡（现状体验，用户已熟悉）；若 R9.4 仲裁已合并多份产出，卡片摘要多一行「已由判官比对 2 份草稿择优」 | 照旧审批合并 | R9.4 |
| 7 | 工作项详情 / 项目主页 | 全部终态后：时间线出「军团复盘」条目（成功 N/失败 M/总成本/学到的记忆条数）；战绩（worklog）计数照旧累加 | 点开看复盘详情 | R9.2 汇总 + R9.3 回灌 |

### 1.2 困难路径 A：子任务卡死/升级
- 触发：某子 run escalate（judge 低置信 / 心跳超时 / 工具失败）。
- 收件箱出 **`escalation` 卡**（kind 已存在）：标题=「《竞品价格调研》卡住了」，reason_text=升级原因（judge 的原话，禁止黑话——「AI 对数据来源不确定」而非「confidence grade 2」），动作=[让它重试][转成我来做（pm_mode）][取消这个子任务]。**其余子任务不受影响继续跑**（部分失败是一等公民）。
- 工作项军团面板：该行状态点变橙 + 「等你决定」标签；面板顶部黄条「1 个子任务需要你拍板 → 去决策」。
- 桌面 Cuu：冒泡（tone=approval）「唔…有个活儿卡住啦，要看看嘛？」→ 点开 = 决策卡牌（同收件箱三动作）。

### 1.3 困难路径 B：预算超限
- 触发：plan/objective 预算耗尽，下一次 enqueue 被 402 拦（R9.5）。
- 收件箱 **`budget` 卡**（kind 已存在）：「《选题调研》军团的预算用完了」，摘要=「已花 ¥1.2 / 上限 ¥1.0，还剩 2 个子任务没跑」，动作=[追加 ¥0.5 继续][就用现有产出收尾][整体收工]。
- 成本页：该 plan 的燃烧条变红 + 同款动作。**绝不静默停摆**——卡片不处理，工作项详情和项目主页都有黄条指回来。

### 1.4 困难路径 C：记忆打架（R9.3）
- 触发：两个子 agent 学到矛盾偏好，diff3 不可调和。
- 收件箱 **`sync_conflict` 卡**（kind 已存在，语义吻合直接复用）：标题=「Cuu 学到了两条打架的偏好」，正文并排展示两条记忆原文 + 各自出处（哪个子任务学的），动作=[要 A][要 B][都不要][合并成一条（可编辑）]。
- 文案原则：把记忆内容原样给人看，不摘要不改写（人在裁决，不是在读转述）。

## 2. 现有流程节点 → 军团扩展点映射（「不变」清单同样重要）

| 现有节点 | 军团扩展 | 明确不变 |
|---|---|---|
| intake 澄清 | 澄清完成后多一步 planner 判定（阈值内无感） | 澄清交互、502 降级纪律（批次 0-2）不变 |
| work_item 状态机 | `ai_working` 期间内部多了 plan/子 run，对外状态机**零新增状态**（军团进度用面板表达，不用状态机表达） | `escalated→{pm_mode,cancelled}` 转移照旧 |
| 提议→审批→合并 | 新增一种提议内容类型（task_plan）；产出提议照旧 | 两段流 approve→merge、评论流、diff 工作台交互不变 |
| 决策收件箱 | +`plan_review` 卡；`escalation`/`budget`/`sync_conflict` 从预留变实装 | 卡片结构/优先级排序框架/键盘操作不变 |
| replay | 子 run 各自有 replay（免费获得） | replay 交互不变 |
| 网盘/交付物 | 多个子任务的交付物照旧按 accepted_deliverable 落盘 | drive 交互不变 |
| 成本页 | +plan/objective 两个聚合维度（新 tab 或分组，见 §3.5） | 既有 me/team 卡口径不变（批次 1-4 纪律） |
| 通知 | +军团事件类型（计划待批/升级/预算/完成），进现有静音分组体系 | 通知 cap/已读语义不变 |

| Cuu 桌宠 | +3 种气泡场景（§3.7） | 气泡玻璃/入场动画规范（批次 0-3 恢复的那套）不变 |

## 3. 逐 Surface 详设

### 3.1 web · 工作项详情「军团」面板（R9.2 切片 2.3 的 UX 定义）

- 位置：现有「AI 处理中」区块原位升级（不是新增第二个区块）。单 run 时渲染现状 UI；有 plan 时渲染军团面板——**同一个卡位，按数据形态切换**。
- 结构（自上而下）：
  1. 头行：`军团推进中 2/4`（或 已完成/部分完成）+ 总成本燃烧条（已花/预算，颜色 <70% 蓝、70-100% 橙、超 红）+「暂停派发」次级按钮。
  2. 子任务行（每行一格，按拓扑序）：`[状态点] [角色徽章] 标题 …… [成本] [产物/动作]`。
     - 状态点：pending=灰空心、dispatched=蓝呼吸动画、succeeded=绿实心、failed=红、等人=橙 + 「等你决定」pill、skipped=灰斜杠。
     - 角色徽章文案：调研/产出/复核/整合（zh），research/produce/review/integrate（en）。**不用图标裸奔，徽章=文字 pill**（CJK 环境图标歧义大）。
     - 依赖未解锁的行：整行 60% 透明度 + 副文案「等待 #2 完成」。
     - 行动作：succeeded → 「看产出」（链到 proposal/replay）；failed/escalated → 「去决策」（链到收件箱对应卡，**不在面板内嵌第二套决策 UI**，决策只在收件箱做——原则 §0.2）。
  3. 尾行（终态后）：复盘摘要一行 +「查看复盘」。
- 状态矩阵：加载=3 行骨架；计划审批中=面板显示计划快照 + 顶部「计划等你批准 → 去审批」黄条；无 plan=渲染现状单 run UI（空态即现状，无新空态）。
- 桌面 Spotlight workitem 视图：同款只读压缩版（头行 + 子任务行，无燃烧条细节），行点击 = 盒子内联 morph 到该子 run 摘要（不开新窗）。

### 3.2 web · 审批工作台的计划提议视图（R9.1 切片 1.3）

- 复用三栏工作台。中栏内容类型判定：提议 payload 是 task_plan → 渲「子任务清单」而非文本 diff。
- 每行可展开：验收标准全文 + 预算份额 + 依赖。行内编辑复用 R4.22/23 React 结构化编辑器模式（受控态在 SSE 下不丢——既有能力）。
- 决策面板按钮（自上而下）：`批准并派发`（primary）/ `批准但先不跑` / `打回重拆`（requires_reason，理由回灌 planner 重拆一次）。
- 防呆：预算份额和 ≠100% 时，「批准并派发」禁用 + 行内红字「预算份额加起来是 92%，还差 8%」。

### 3.3 决策收件箱新卡（4 种）

- 契约：`plan_review` 需新增进 `attentionItemSchema.kind`（其余三种已预留）。**枚举新增三同步**（xlink-contract 教训）：web route-components 渲染分支 + 桌面 cuu cards 分支 + 双语文案表，缺一即算未完成。
- 排序优先级（插进现有框架）：escalation(urgent) > budget(high) > sync_conflict(high) > plan_review(normal) > proposal_review(normal)。
- 每种卡的动作按钮 ≤3 + 查看详情；所有按钮动词用「人对 AI 说话」的口吻（「让它重试」不是「重试任务」）。

### 3.4 web · 项目主页

- 「进行中的工作」小节里，军团工作项的行尾加 pill：`军团 2/4`。点击行为不变（进工作项详情）。**不加新小节**——项目主页已经过 R8 的信息架构收敛，别再膨胀。

### 3.5 web · 成本页

- 新增分组维度切换：`按人 | 按军团计划 | 按目标`（后两个 R9.5 后出现；无数据时不渲染切换器，不渲染空 tab）。
- 每个 plan 一行：名称 + 燃烧条 + 子任务数 + 状态。超限行红色 + 「去处理」链到 budget 卡。

### 3.6 web · `/dashboard/agents` 指挥台（R9.6 详设）

- 布局（桌面宽）：
  1. 顶部 KPI 行（4 张小卡）：进行中军团数 / 等你决策数（点击=回 home 收件箱，**不在 dashboard 内做决策**）/ 今日成本 / 自治率（北极星，复用现有指标）。
  2. 主区：每个活跃 plan 一张玻璃卡（栅格 2 列，移动端 1 列）：工作项标题、进度 `2/4`、角色徽章排、成本迷你条、最老卡点高亮（「卡在:竞品调研 · 2h」）。卡片点击=进工作项详情（不是进 dashboard 二级页——dashboard 无二级页）。
  3. 右栏（窄）：最近升级/决策流水（只读时间线）。
- 空态（无任何军团时）：一段引导文案「还没有军团在跑。下次遇到大活儿，Cuu 会先给你一份分工计划。」+ 链到 intake。**不放假数据、不放教程图**。
- 移动端：KPI 2×2、plan 卡单列、右栏折叠为「最近动态」手风琴。**禁用定高 line-clamp**（CJK 溢出门）。
- 玻璃：web 端用现有 `.wh-card` 玻璃质感类；桌面 Spotlight 的 army 视图走 main 窗 vibrancy + 既有 ds 类。**禁止新 transparent+backdrop-filter**。

### 3.7 桌面 · Spotlight 与 Cuu

- Spotlight 新能力 `军团`（关键词：army/军团/agents/小队）：细搜索条输入即匹配 → 盒子生长出活跃 plan 列表（≤5 行，同 §3.6 plan 卡的压缩版）→ 选中 morph 到 plan 详情。Esc 逐级回退（详情→列表→收起），遵守既有 Spotlight 生长/morph 时序（盒子先长、内容后现）。
- Cuu 气泡三场景（二次元人设，文案示例，最终以 cuu/i18n 表为准）：
  - 计划待批：「这个活儿有点大！Cuu 拟了个分工方案，帮我看看嘛？」[看看计划]
  - 升级：「呜…《竞品调研》那边卡住了，需要你拿主意。」[去看看][晚点]
  - 全部完成：「军团收工！4 个活儿都办完啦，去验收吧～」[去验收]
  - 频率纪律：同一 plan 的气泡合并节流（5 分钟窗口内只冒最高优先级一条）；`suppress_bubble_intro` 机制照旧防重播。
- Cuu 决策卡牌：plan_review 卡进卡牌体系，**标题必须带工作项名**（批次 3-6 教训：禁止通用文案覆盖导致认不出是哪个变更）。

## 5. 灰度与渐进披露

1. **阈值即开关**：planner 触发阈值（子任务数 ≥2 且预估成本 ≥某值）配置进 `packages/config/src/env.ts`（如 `ARMY_PLAN_MIN_SUBTASKS`，默认值先设高=事实灰度）。**不做独立 feature flag 开关面板**——调阈值即灰度。
2. 渐进披露顺序 = 施工顺序：用户先只会遇到 escalation 卡（R9.0）→ 再遇到计划卡（R9.1-9.2）→ 记忆/预算卡（R9.3-9.5）→ 最后才有 dashboard（R9.6）。每阶段用户学习成本 ≈ 一张新卡片。
3. 第一次收到 plan_review 卡时，卡片尾部加一次性说明行「这是什么？大活儿 AI 会先拆分工计划给你过目」+ [知道了]（存 user preference，之后不再显示）。

## 6. UX 验收清单（并入各阶段验收门）

- R9.0：收件箱 escalation 卡真实渲染（web+桌面）、reason_text 无黑话、三动作各自转移正确、Cuu 冒泡节流生效。
- R9.1：计划提议在审批工作台可读可改可打回；预算份额防呆；「先不拆」路径回到单 run 现状。
- R9.2：军团面板五种状态点齐全、部分失败不阻塞其余、决策永远跳收件箱不内嵌；Spotlight 压缩版渲染。
- R9.3/9.5：sync_conflict/budget 卡动作闭环（处理后卡消失、面板黄条消失）。
- R9.6：dashboard 空态/移动端/玻璃规范；KPI「等你决策数」与收件箱实际数量一致（跨页计数一致性——xreview 老病，写测试钉住）。
- 全程：每张新卡/新面板都有 loading/empty/error/partial 四态定义，裸奔任何一态算未完成；web smoke 步数与计数门同步更新并注明。
