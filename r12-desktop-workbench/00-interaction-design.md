## 0. 一句话与设计原则

**把桌面端从「聚焦盒工具」升级为「项目工作台」：每个项目一个群聊主区,人和 AI 在同一条消息流里工作;讨论停下来 60 秒,AI 把话头里的活儿拎出来自己干;军团进度就挂在每个会话旁边。**

继承、不违背的既有纪律:

1. **写生产必走「提议→审批→合并」**——群聊里 AI 再自动,产出落地仍是提议,一条不破。
2. **太上不知有之**——AI 干活尽量安静,行动卡是敲门,不是刷屏。
3. **去黑话**——行动卡话术复用置信度三话术(我比较有把握/建议你扫一眼/我拿不准,你来定)。
4. **Cuu 人格唯一**——群聊里的项目 AI 就是 Cuu 本人,桌宠、气泡、群聊发言同一只猫。
5. **跨工作区隔离与预算硬闸**——run 无论从哪个入口派生,预算 reservation 与 workspace 边界照旧。

已拍板的四个分叉(2026-07-12 用户拍板):

| 分叉 | 决定 |
|---|---|
| 主窗形态 | **Spotlight 唤起工作台主窗,两者并存**——类比安卓桌面的 Chrome 搜索框 vs 完整浏览器:聚焦盒是快速层,点开项目即唤起常驻主窗 |
| AI 自动力度 | **默认分级自动,人可配置**——高把握直接干(可撤销)/中把握先问/低把握只观察;档位个人可调、项目可覆盖 |
| 军团进度位置 | **挂在每个会话右侧**——像 subagent/workflow 面板:会话派生的 runs 就在该会话旁边看;全局只留轻量总览入口 |
| Cuu 角色 | **Cuu 就是项目 AI**——群聊头像/名字/表情即 Cuu,桌宠与群聊同一人格,重要行动卡桌宠弹气泡呼应 |

2026-07-12 三次纠偏(用户拍板):**主区群聊的观察者固定全自动派活**——群里人多,不设「等谁点头」的实时确认;执行类事项直接干(撤销窗兜底),决策类事项 @建议负责人并进 attention 异步拍板;「谁来确认合并」的答案是提议→审批(有归属、异步、可回滚),不是群里按钮。**模式五档只属于成员与 Cuu 的单聊(协同会话)与个人默认设置**,不出现在主区。**项目工作区 git 化**:一切产物版本化可回滚(复用 branches/snapshots/proposals 与 project_drive_versions)。

- **Spotlight 不删不改职责**:仍是全局搜索与能力速查;新增一类结果「打开 XX 工作台」与深链(`workhub://workbench/<projectId>/<conversationId>`)。工作台内 `⌘K` 复用同一 command palette。
- **新建项目是原子动作**(2026-07-12 补):左栏项目列表尾部与 Spotlight 都有「新建项目」;创建即自动配好**主区群聊 + 项目网盘 + Cuu 入驻 + 默认模式(分级自动)**,零二次设置就能开聊;成员邀请与权限在项目设置里补。服务端复用现有 projects 创建端点,扩展为同事务建内置会话。
- **主窗是新的常驻容器**:macOS 玻璃窗(复用 ds-glass 与 vibrancy 约束——毛玻璃靠原生 vibrancy,不指望 CSS backdrop-filter)。
- **右栏是「情境面板」**(交互参照 Codex app 右栏,2026-07-12 用户补充拍板):默认按会话分三区——**输出**(本会话产物:草稿/提议/已合并交付物,点击进预览或提议 diff)、**军团**(本会话派生的 runs,点击卡片**下钻详情**:时间线+产物+中止/交接/回放操作,可返回)、**后台任务**(该项目的定时/常驻任务,如竞品日报、夜间技能整理)。选文件卡→预览态。可收起。

## 2. 项目主区群聊

### 2.1 成员与消息类型

- **主区就是项目组全员群聊**:项目人类成员全员可发言、互相 @、丢文件,Cuu 是一等成员而非旁观 bot;顶部成员条常显头像与在线状态,有「XX 正在输入」;**刻意不做已读回执**(不造打卡压力,触达靠 attention 队列与 Cuu 气泡)。
- 消息类型:
  1. 人类文本(支持 @成员、@网盘文件、#其它会话引用)
  2. 文件卡(引用或上传——拖文件进聊天 = 存入项目网盘 + 发一张文件卡)
  3. 系统事件卡(静默样式):提议已合并、run 完成、成员加入——折叠聚合,不刷屏
  4. **Cuu 行动卡**(见 2.3)
  5. Cuu 普通发言(被 @ 时回答问题,不必产生行动)

### 2.2 60 秒静默观察者

- **触发条件**:最后一条消息后 60s 内无新消息(参数可配,项目级)**且**自上次分析后有新讨论内容。二者缺一不触发——保证同一段讨论只被消化一次,绝不重复出卡。
- **触发中 UI**:Cuu 头像出现在输入区上方,微呼吸 +「正在整理刚才的讨论…」。**不做倒计时**——倒计时制造「说话打断 AI」的压迫感,违背"不知有之"。
- **分析输出三种结局**:
  1. 没活儿 → 什么都不发(静默退场,头像淡出)。
  2. 有可处理工作 → 发**一张**行动卡。
  3. 讨论里有直接问 Cuu 的问题 → 普通发言回答。

### 2.3 行动卡(核心交互物)

```
┌──────────────────────────────────────────────┐
│ [Cuu] 从刚才的讨论里拎出 2 件事                 │
│                                              │
│ ① 把选题报告初稿按张三说的口径重写第三节        │
│    我比较有把握 · 已开工 ▸ 运行中(军团可见)     │
│    [撤销](10 分钟内可点,撤销即 abort run)      │
│                                              │
│ ② 下周投放预算是否砍半                         │
│    我拿不准,你来定 · @阿曼                     │
│    [交给我干] [派给别人…] [先不动]              │
└──────────────────────────────────────────────┘
```

- **主区观察者固定全自动派活**(2026-07-12 纠偏:群聊人多,不做「等谁点头」的实时确认)。行动卡条目分两类:
  - **执行类**(AI 能直接干的活):一律直接建 work_item + 派 run,卡上给**撤销窗口**(撤销 = abort + work_item 关闭 + 线程留痕);把握度只影响话术呈现与 judge 复核强度,不影响「干不干」。**合并确认由提议→审批承担**——有归属(负责人)、异步、可回滚,这就是「谁来确认」的答案。
  - **决策类**(业务拍板、AI 不该替人决定的,如「预算砍半?」):@建议负责人 + 进 attention 决策队列,负责人在群里或收件箱任一处拍板;卡上按钮(交给我干/派给X/先不动)是给**被 @ 的负责人**的,不是给全群的。
- **项目治理开关**(负责人在项目设置里调,不是五档模式):观察者开/关、静默窗口时长(默认 60s)、安静时段、Granular 能力细分(建任务/派 run/动网盘/发通知)。
- **防刷屏**:每个静默窗口至多一张行动卡;若上一张卡还有未处理项,新分析**追加进原卡**(卡片原地更新 + 轻标记"更新了"),不另发新卡。
- **进度线程化**:行动卡下挂线程(不占主流):run 状态变化、产出的提议链接、升级求助都回贴在线程里。主流里只在**终局**(提议待审/完成/升级)时冒一条可点的摘要。

### 2.4 升级进群聊

run 升级(escalated)时,行动卡线程里贴升级卡:「做了什么/卡在哪/建议下一步」+ @建议负责人——即 R9.0 逃生舱的群聊呈现面。决策收件箱(attention)照常收录,两处点开同一实体。

## 3. 协同会话(chatbox)

- **新建入口**:左栏协同区「+」;或行动卡上「深入处理」(把该事项连上下文拆出去单聊);或从工作项/提议页「和 Cuu 聊这个」。
- **形态**:就是正常 chatbox——1:1 人机为主,可拉其他成员;Cuu 流式回复;工具调用折叠成行内 chips(codexia 式:`读取 报告.md ✓`,可展开看详情);长任务自动转后台 run(军团面板可见),聊天里贴进度。
- **引用语法**(wisp 式,主区 composer 同):`@` 网盘文件/成员 · `#` 引用其它会话(含主区某段) · `/` 技能(team_skills)。
- **模式五档只属于单聊**(2026-07-12 纠偏后归位):每个成员在自己的协同会话里选**自己的**模式——个人默认在 设置 · AI,会话内 composer 可就地调,数字键 1-5 快切,composer 常显当前模式,全托管用警示色:

| 档位 | 观察者 | 执行 | 审核合并 |
|---|---|---|---|
| 1 只观察 | 只总结 | 不执行 | — |
| 2 全部先问 | 提出方案 | 任何执行等我点头 | 人审 |
| 3 分级自动(默认) | 提出 | 高把握直干(可撤销)/中先问/低只列 | 人审 |
| 4 全自动 · 人审 | 提出 | 拎出的事全都干 | 人审 |
| 5 全托管 · AI 审 | 提出 | 全都干 | **AI 复核通过即自动合并**——复用置信度矩阵「仅 grade5 auto-merge」;法务/财务/身份等高风险类别永远升级给人,不可关闭 |
- **产出卡内嵌消息流**(Codex app 式):Cuu 改完东西在聊天里落一张「已起草 XX · +86 -12」卡,带**撤销/交给审核**两键——审核即走提议线,撤销即语义化取消;不让产物只活在右栏。
- **记忆引用可折叠**:Cuu 的关键发言下挂「N 条记忆引用」折叠行,展开可见依据了谁说的话/哪条团队技能——把 user_memories/team_skills 的注入变成可见的信任证据。
- **会话转正**:聊出来的结论一键「变成任务」/「变成提议」——把口头共识固化进正式流。
- 协同会话属于项目,默认成员可见(左栏列出);可标记为私密(仅参与者)。

## 4. 军团面板(会话右侧)

- **归属逻辑:军团是会话的派生物**。每个会话(主区/协同)右侧可展开「军团」面板,只列**本会话派生**的 runs——像 IDE 里的 subagent/workflow 面板,进度不离开上下文。
- **卡片**(codexia AgentCard 式):
  - 头部:角色/目标一句话/发起自哪条消息(点击回跳);
  - 身部:实时步骤 chips(最近 3 步,`想→调工具→看结果` 摘要),运行中有呼吸态;
  - 尾部:状态(排队/运行中/等审批/完成/升级/失败)· 成本(实报) · 执行者身份(谁的 agent);
  - 操作:中止 / 交接(handoff) / 看完整回放(trace→右栏 replay 视图)。
- 过滤:全部/进行中/等我拍板/已完成。
- **点击卡片下钻详情**(Codex app 式):面板内切到该 run 的详情视图——目标、执行身份、成本、**时间线**(认领→读料→产出→提议,逐步带时间戳)、产物列表、操作按钮;「返回军团」回列表。完整回放仍走 replay 视图,详情是轻量层。
- **军团成员有名字**:每个 run 除角色外配一个易认的代号(如 阿墨/雪球/橘皮——Cuu 麾下的猫仔),输出区、线程回贴、通知里都用名字指代,跨面板认人比 run id 友好;Cuu 仍是唯一对外人格,成员名只是任务代号。
- **层级预留**:R9.2 `parent_run_id` 落地后,卡片可展开成子 run 树——面板结构按「卡=节点」设计,一开始平铺,后天然长成树。
- **全局轻总览**:左栏底部「军团总览」——聚合我可见项目的 runs 计数(如「3 运行中 · 2 等拍板」),点开是按项目分组的同款卡片流。**不做重型指挥中心**,遵 R9 路线图"指挥台等真数据"。

## 5. 网盘(项目绑定)

- 左栏每个项目下常驻「网盘」节点,中栏打开 = 复用现有桌面 drive 能力视图(`spotlight/views/drive.ts` 迁移进工作台,数据层 `project_drive_*` 四表现成)。
- 与聊天互通:
  - composer `@` 直接搜索并引用盘内文件 → 聊天里成文件卡;
  - 文件卡点击 → 右栏预览(文本/图片直预览,其它给下载);
  - 拖文件进聊天 = 上传到本项目网盘 + 发文件卡(落默认「聊天上传」目录,可移动);
  - AI 产出的交付物合并后自动归档进网盘对应目录,群聊冒系统事件卡。
- **项目工作区 git 化**(2026-07-12 补):一切产物版本化、可回滚——网盘文件自动留版本(`project_drive_versions` 已有),文档类产物走 工作副本→提议→合并 且留快照(`branches`/`snapshots`/`proposals` 复用),任何合并可一键回滚;文件卡/网盘条目可看版本历史。**「敢让主区全自动派活」的底气来自这里**:干错了不是灾难,是一次回滚。

## 6. 任务派发:「派给谁,就在谁的 agent 里跑」

- 行动卡/协同会话里指派(派给张三)时:
  - **张三的接单策略先说话**(2026-07-12 补,个人设置三档,默认自动):`自动接单`=自动建工作副本+他的 agent 立即开工,Cuu 气泡只告知;`先问我`=确认后才开工;`只挂单`=进任务列表手动启动。**接单即建工作副本(branch)**——执行全程产物锚在副本,人可中途查看/插手/接管,合并仍走服务端审核,红线不变;
  - run 以**张三的执行身份**入队:注入张三的 user_memories、技能上下文、预算 scope,成本 labor-split 记到张三名下;
  - run 出现在张三视角的军团面板(和他自己发起的一样),**张三的 Cuu 弹气泡**:「阿曼在星尘项目派了个活给我,我开工了喵」;
  - 张三可接管(进协同会话补指示)、改派、或打回(带理由,回灌原会话线程)。
- **审核永远在服务端;执行可下放本地**(桌面执行器为后置批 9):judge/合并/预算/审计是信任链,不跑在可被篡改的客户端;完整用户流与数据流(含本地/服务端双执行面、llm-proxy、信任边界表)见 [03-user-and-data-flows.md](03-user-and-data-flows.md)。
- 与现有 `work_item_assignments` 对齐:指派即 assignment,run 执行者=assignee。发起人保留可见性(线程里看进度)。
- 类似 goal 模式:人给的是目标与边界,执行在被指派者的 agent 语境里自治,升级时回到人。

## 7. AI 配置服务端化

- **桌面零 key**:客户端任何 AI 能力都走服务端 API(现状 agent loop 本就在服务端,此处是把纪律固化为约束:客户端代码禁止出现 provider key 路径)。
- 设置页「AI」改为**服务端下发的只读配置 + 个人可调偏好**:
  - 只读:可用 provider/模型档位、我的预算额度与本月用量(复用 cost 页数据);
  - 可调:单聊模式默认档(五档,见 §3)、Granular 细开关、Cuu 主动性(气泡频率)、模型档位偏好(在管理员允许的档位内选);
- 管理员在 web 端管 key 与档位白名单;桌面端只消费 `GET /api/me/ai-profile`(新端点)。

## 8. Cuu 打通

- 群聊 Cuu、协同 Cuu、桌宠 Cuu、Spotlight 气泡 Cuu **同一人格同一记忆**(桌宠已订 /me 流,复用)。
- 联动规则(避免双重打扰):主窗前台时事件只在窗内呈现;主窗最小化/后台时才走桌宠气泡+系统通知;点气泡深链拉起主窗定位到对应会话/行动卡。
- 桌宠状态呼应:项目里有 run 在跑→桌宠偶尔「专注工作」小动作;有卡等拍板→桌宠举小牌子。彩蛋级,不做保证送达的通知通道。

## 9. 关键状态与空态

| 场景 | 处理 |
|---|---|
| 新项目空群聊 | Cuu 开场白:项目是什么、拉谁进来、丢个文件或说句话就能开工——引导第一条消息 |
