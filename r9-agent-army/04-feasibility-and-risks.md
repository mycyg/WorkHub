# R9 · 可行性与风险

> 结论先行:**可行,而且最难的后端(agent 引擎、记忆/技能/成本雏形、提议→审批纪律)WorkHub 已经造了一大半。** R9 不是从零,是把"单 agent 接任务"升级成"军团编排"。成败不在 agent 跑不跑(已验证),在编排层四件难事 + 一条不能碰的红线。

---

## 1. 三层分类:真的能成 / 难但能做 / 是虚构

### ✅ 已经成立(WorkHub 已验证或已有雏形)

| 能力 | 现状 | 证据 |
|---|---|---|
| agent 端到端执行 | 已验证 | R5.10 真 DeepSeek key 跑通 6 AgentRun,质量 4–5,¥0.142 |
| 层级拆解的载体 | 已有 | AgentRun / proposal / work_item / 部门雏形 |
| 证明驱动完成 | 已是习惯 | gate / output-contract / gold-path / PG smoke 当证明 |
| 记忆 + 技能复利 | 有雏形 | SkillOpt K1 记忆 / K3 学习率 / K5 成本分账 / 自进化战绩 |
| 提议→审批→合并护栏 | 已是内核 | 业务版 GitHub,改动留快照可回滚 |
| 合并冲突原语 | 已有 | P-COLLAB:序列化锁 + base 快照 + diff3 祖先 + rebase |

> 含义:R9 是**在地基上盖编排层**,不是推倒重来。这是它可行的根本原因。

### ⚠️ 难但能做(真正的工程前沿——R9 的全部价值在这)

1. **拆解的泛化**
   固定的"产品/研究/增长/工程"四部门对短剧工厂好使,对"任意人类任务"泛化很差。
   **做法**:meta-planner 现场为每个任务设计组织(角色 + 子任务 + 验收标准),或维护一套按领域分的组织模板库,planner 选模板 + 微调。质量直接决定整套灵不灵。
   **风险**:planner 拆错 → 整条链白跑。缓解:拆解结果先过一道"人确认/可编辑"或 LLM-judge 自检,再派发。

2. **记忆三层架构 + 冲突归并**(详见 `02-memory-architecture.md`)
   隔离不难,**协调难**。A 子 agent 的记忆和 B 的打架时谁和解?
   **做法**:私有记忆(每子 agent)+ 共享治理记忆(OKR System)+ 收割技能记忆,三层读写边界前置定义,冲突复用 P-COLLAB 的合并纪律。
   **风险**:不前置设计 → 记忆腐烂 / 相互矛盾 / stale(已有"dev API stale"预兆)。

3. **证明的定义**
   代码有测试/CI(客观);"调研热门题材""营销文案"证明是模糊主观的,只能上 LLM-judge,而 judge 会被糊弄。
   **做法**:客观处硬门,模糊处 LLM-judge + 对抗式多票验证(参考 WorkHub review 那套多 agent 对抗),judge 内置进主 agent 但**对自己的产出不自评**(交叉验)。
   **风险**:judge 与执行同源 → 自我背书。缓解:judge 用不同视角/不同 prompt,或独立一票。

4. **人类逃生舱 + 成本天花板**
   长周期自治的安全阀。
   **做法**:决策信箱(复用 attention 队列)+ 预算硬上限(见 §3)。先修"escalated 死状态"坑——`work_items.escalated` 从没被置过,升级流得真的能把任务推到 escalated,人才看得到。
   **风险**:happy-path UI 藏起 partial failure / 卡死 / 假装 done → 用户以为一切 healthy。

### ❌ 虚构 / 红线(明确不做)

- **"agent 自动办实体 / 银行卡 / 域名 / 邮箱,从第一天赚钱"** —— KYC / 验证码 / 法律责任卡死,且属于"必须人来做"的高风险动作。R9 把这些**永远升级给人**,framing 改成"agent 辅助 + 人过法务/财务/身份关口"。
- **"0 人公司 / 无人值守"** —— 与自主率护栏"绝不拿信任去换"冲突。R9 = 1 人指挥 + 巨型军团,人始终在中心。
- **happy-path 演示** —— 困难状态必须是一等公民,不准藏。

---

## 2. 与 WorkHub 现有护栏的一致性检查

R9 必须继承、不能违背的既有底线:

- **AI 任何改动不悄悄写进生产** → 军团里每个子 agent 的产出也走提议→审批→合并,不直写 main。
- **北极星=自主率,但绝不拿信任换** → 军团提高的是自主率的"分母覆盖面",护栏(回滚率/打回率/升级准确率)同步盯。
- **去黑话** → 对用户说"军团/任务/技能/记忆",不说"DAG/scheduler/swarm"。
- **跨工作区隔离**(R3 审查发现过工作项跨工作区写的洞)→ 子 agent 的记忆/技能/写操作必须钉死租户与工作区边界。

---

## 3. 预算:做成一等的、可见的、有硬上限的资源

灵感稿把 "TOKEN COST ↓$82.10" 放在最显眼处是对的。R9 的预算设计原则:

1. **每个 Objective / 任务带预算上限**(token 或 ¥),不是全局观测,是**硬门**:花到上限,后续子 agent 派发被阻断,升级给人决定"加预算 / 收工 / 改范围"。
2. **预算可见**:dashboard 常驻显示"本周期已花 / 上限 / 预测",像灵感稿那张玻璃 widget。
3. **复用现有**:WorkHub 已有 cost / cost-labor-split / ai-worklog-metrics,把"观测"升级成"带 ceiling 的资源账户"。
4. **军团放大成本风险**:N 个子 agent × 长周期 = 成本平方级。预算门是防失控的核心闸。

---

## 4. 一句话风险地图

> 能不能成,不取决于 agent 跑不跑(已验证),取决于:**meta-planner 拆得准不准、记忆会不会腐烂、证明能不能防自证、人类阀门和预算闸有没有真的拦得住失控。** 把"0 人自动办银行卡"降级成"人过关口",其余都站得住。
