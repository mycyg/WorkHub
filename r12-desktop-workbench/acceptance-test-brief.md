# R12 桌面工作台 · 人工验收测试任务书

> 给测试人员的正式任务书。操作步骤的详细脚本在 [demo-walkthrough.md](demo-walkthrough.md)（含建号/建项目的 curl），本文规定**测什么、什么算过、交什么**。
> 背景：逻辑层已有 3000+ 自动化测试兜底，你们要测的是机器测不了的部分——真机视觉、多人实时体感、通知打扰、真 LLM 行为。

## 0. 环境要求（开测前逐项确认）

1. **必须是真 .app**（`cargo tauri build` 或 dev 运行的 Tauri 客户端）——毛玻璃、系统通知、窗口行为在浏览器里根本不存在，浏览器里测视觉线等于白测。构建基线：main 分支，记下 `git rev-parse HEAD`。
2. **双账号**：阿曼（项目负责人）+ 张三（成员），建号命令见 demo-walkthrough §0。最好两台机器；一台也行（桌面客户端跑阿曼，浏览器跑张三的 web 端）。
3. **真 LLM key**：观察者、协同会话两条线必需，找管理员配到 API 环境。没 key 时 B/C/G 三条线标「阻塞」跳过，不要硬测。
4. **API 日志留底**：启动 API 时输出 tee 到文件（失败分诊要用）。
5. 截图用 macOS 自带截屏（⇧⌘4 或 `screencapture`）——远程抓屏工具抓不到透明 vibrancy 窗口。

## 1. 测试范围与合格标准（七条主线）

### A. 群聊闭环（步骤：demo-walkthrough §1）
双人在同一项目主区互发消息、@ 对方、发网盘文件卡。
**合格**：对方消息 3 秒内出现；「正在输入」出现且停手后约 3 秒消失；文件卡可点、右栏出预览；把一台机器断网 30 秒再恢复，消息一条不丢、一条不重、顺序不乱。

### B. 观察者行动卡（步骤：demo-walkthrough §3）
群里讨论出可执行的活，停止说话等 60 秒。
**合格**：行动卡出现且拎出的事项与讨论对得上；执行类事项显示「已开工」；被派活的张三收到 Cuu 气泡问询（话术是「要不要接」而非「已开工」）；**行动卡按钮（交给我干/派给别人/先不动）只有被 @ 的负责人能看到可点态**，其他人只见「等 @某某 拍板」；点「撤销」后条目置灰划线，另一端（不刷新）几秒内同步；张三在 web 审批队列里处理同一条升级后，桌面行动卡刷新后状态一致（不再出现「永远待拍板」）。

### C. 协同会话（步骤：demo-walkthrough §2）
**已知限制**：UI 暂无「新建协同会话」入口，用脚本里的 curl 建好再测。
**合格**：发消息后出现「Cuu 正在回复」+流式打字；最终回复落定成正式消息（含记忆引用可展开时正常显示）；Cuu 回复中再发一条会得到温和提示（该条不自动重试——已知限制，不算 bug）；把自己的模式调到「只观察」再发消息，被拒且提示指向输入框旁的「模式」按钮。

### D. 模式五档
**合格**：模式 chip 只在协同会话出现（主区没有）；弹层五档齐全、第 5 档「全托管 · AI 审」选中时呈警示色；弹层开着按 1-5 能切档；**焦点在输入框里打数字 1-5 不会误切档**；切到只观察后立即生效（发消息被拒）；断网时切档失败有提示且档位回滚。

### E. 网盘与版本回滚（步骤：demo-walkthrough §4）
**合格**：上传/列表/面包屑正常且界面有正常样式（玻璃卡片，不是裸 HTML）；同名文件再传后版本历史多一条；「找回这个版本」后生成新版本、历史一条不少；回滚后群聊主区冒出系统事件卡；聊天里的文件卡和网盘标签打开的是同一个右栏预览。

### F. 视觉/窗口/打扰（只有真机能测，重点）
**合格**：
- 工作台窗口是毛玻璃（能透出桌面壁纸的模糊感，不是纯黑实底）、四角圆角无黑边残角；
- 拖标题栏可移动窗口，最小化/关闭（关闭=隐藏）正常，隐藏后从 Spotlight「打开工作台」能再唤起且状态还在；
- 打扰矩阵：正盯着某会话时，该会话新消息**不**弹桌宠气泡；切到别的项目后，行动卡/派活类事件**会**弹 Cuu 气泡，点气泡深链回到工作台对应项目；普通消息不触发 OS 级系统通知（不轰炸）。

### G. 全托管自动合并（可选，耗时长）
把张三模式调到 5，让观察者派给他一个能拿高分的活，等 run 跑完。
**合格**：提议被自动合并、群聊出现「已自动采纳 · 全托管」产出卡；对照组：模式 ≤4 的用户同样的活只开提议等人审。

## 2. 已知问题清单（遇到不要报，报了也会被关掉）

1. 协同会话没有 UI 创建入口（curl 建）
2. 右栏「输出/军团/后台任务」三区是「即将上线」占位（故意的）
3. web 设置页没有 AI 模式/接单策略入口（桌面弹层是目前唯一入口）
4. Cuu 回复中发的第二条消息不会自动重试
5. Cuu 气泡深链只到项目主区，到不了具体行动卡
6. App 完全没启动时点系统深链可能丢（冷启动重放未做）
7. 托盘菜单没有「打开工作台」项
8. @ 选人器不支持键盘上下选择
9. 观察者建的工单在 web 详情页来源说明缺失（显示像自己提交的）

## 3. 判定线

- **A–E 全过 + F 的前两组（玻璃/窗口）过 = 验收合格**。
- F 打扰矩阵或 G 失败 → 记「已知降级」，不阻塞合格，但必须写清现象。
- A–E 任何一条失败 → 不合格，按 §4 格式交材料打回修复。

## 4. 交付材料（交什么、什么格式）

一个 markdown 报告 + 一个截图/录屏文件夹，打包交回。报告须含：

1. **结果总表**：七条主线 ×（通过/失败/阻塞）+ 每条一句话结论。
2. **每个失败项**（一项一节）：
   - 复现步骤（编号列表，从哪个账号哪个界面开始）
   - 预期 vs 实际（各一句话）
   - 截图或录屏文件名 + 失败发生时刻（精确到分，用于对 API 日志）
   - 当时用的账号和机器
3. **环境信息**：.app 构建 commit、macOS 版本、API 是否带真 key。
4. **附件**：API 日志文件；桌面端如见白屏/报错，附 webview console 截图（右键 → 检查元素 → Console）。

失败项照这个格式给全，我可以直接分诊修复，不用来回追问。
