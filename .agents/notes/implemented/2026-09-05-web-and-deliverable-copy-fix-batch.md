# 网页端与交付物文案修复批：界面不再解说自己，交付物只写产品内容

- Status: implemented
- Date: 2026-09-05
- Owner: claude（r26/f2-web-copy-fix 工位，F2）

## Problem

审查员 A2 逐文件读完 `apps/web`、`packages/ui`、`packages/web-runtime`、`apps/api/src/pages`、
服务层与技能合同，出了 96 条（16 高 / 74 中 / 6 低）。它们不是零散错字，是四条系统性裂缝：

**一、界面在向用户解说自己的设计。** 每个路由的加载/空/错误/403 态正文是设计规格原文
（en 侧「The page waits for the backend service instead of showing fake success.」「Empty states
stay quiet and leave a create, back, or history entry.」——这是写给评审看的「空态该怎么设计」）；
每一页右栏常驻一块「数据源 / 实时数据 / 数据以后台为准」，本质是开发期「我不是假数据」的自证；
设置页四条把分层决策与 `shared contracts` / `client layer` 写给用户；还有一整组已入库但从未渲染的
`masthead.*`（十七条「X 页汇总 Y」，夹着「项目即产品」和 repo/PR 的 git 心智）。

**二、内部实现词与裸 id 一路透到界面。** 成本页「按人花费」除自己以外每行标签就是完整用户 uuid；
回放页每条证据标题是「`proposal.merge` audit」；预算状态缺值时直出枚举 `ok`；结构化字段卡渲
「策略: accept_incoming」「快照: 8f2a13cd」；冲突卡正文写着「不用看技术细节」，旁边挂着两串 sha256。

**三、英文侧完全绕开禁词门。** `option-first` 已在禁词表里，却在**被扫描的同一个文件里**存活两处
——门禁只检查含中文的行，而 gold-path 词典的 zh/en 是分块写的。

**四、AI 融合交付物把合并过程当成了交付内容。** 采纳「AI 融合稿」后真正落进项目网盘、用户会打开的
那份文件，标题自称「AI 融合正式稿」，前四行是 Proposal ID / Merge Proposal ID / 冲突 key /
`候选来源：unknown`，接着是 AI 自己的融合理由，最后把内容塞进 JSON 围栏。

同时，同一个实体在界面上有四个名字（任务 / 工作项 / 事项 / 工单），AI 小组有三个名字
（军团 / 智能代理军团 / 指挥台），快照与还原点、自主率与自治率并存，「令牌」一词同时指邀请码与 token。

## Decision

**先在 glossary 落权威用词表，再机械替换，不逐条即兴改词。** `docs/workhub/00-overview/
glossary-dejargon.md` 新增 §11「用户面权威用词」：一个概念一行，左边权威中英说法，右边「不再使用」
的其它叫法。改词时对着这张表改，而不是每处现编——`docs/workhub/07-open-questions.md` 记过一次
「R9-OQ-NAMING-PASS 已解决」而实际没收敛，就是因为上一轮没有这张表。

**兜底不再摊平枚举，缺映射改成在测试里红。** `labelFromMap` 之前未命中就 `uiHumanize`（下划线换空格）
直出，于是任何新枚举都会以 "Foo Bar" 的形态出现在界面上。现在回落到该维度的中性词（「其他状态」
「其他类型」…）并把 `维度:值` 记进登记簿，`packages/ui/src/i18n.test.ts` 断言渲染完契约里全部枚举后
登记簿必须为空。**这比抛错好**：一条脏枚举不该把整页搞炸；也比摊平好：缺映射会在 CI 红，不会在用户面红。

**裸 id 的处理是「换成人话或整条不渲」，不是截断。** 审计行只说改的是什么类型的东西，成本分组行
拿不到名称就不渲那一行，依赖 pill 取不到任务编号就整条略过。id 全部保留在 `data-*` 属性上，取证与
自动化不受影响——「id 前 8 位」对用户从来没有信息量，截多截少都一样。

**洗词层降级为「只兜模型自己写的话」，并给每条规则配测试。** `cross-agent-judge.ts` 的
`publicReviewCopy()` 曾有 20 余条正则，其中「R9.4 cross-agent judge arbitration」这一条本身就证明
轮次代号进过用户可见文本。做法是：服务端自己产出的英文 reasons/summaryMd 在源头改写成中文产品语言
（提示词第 272 行本来就这么要求模型），洗词表只留模型可能回抄的 12 条（JSON 里的 `accept_one`/
`merge`/`confidence` 这些枚举名与英文标签），每条在 `cross-agent-judge.test.ts` 有一行断言。
**没有测试的规则不留在表里**——那正是死条目滋生的地方。

**交付物只写合并后的内容本身。** AI 融合稿的正文改成「# 变更申请标题」+ 合并后的字段（数组按条列，
文本直出），id、冲突 key、选中的方案、AI 的融合理由、JSON 围栏全部移出正文——它们已经在变更申请页
与回放里，进文件只是把过程记录冒充成交付物。兜底文件名也从 `<change_id>.ai-fusion.md` 改成用变更申请
标题（新增 `safeVisibleFilenameSegment`：保留中文，只挡路径分隔符与控制字符；内部 id 目录段仍走
纯 ASCII 的 `safeStorageSegment`，两者不混用）。

**提示词在源头不要求英文自述。** 工作纪律第 2/4/7 条曾强制模型「在总结中列为 blocker」并把
`[sandbox: … denied by policy]` 抄进总结；第 3 条的三行模板首词是「完成了：」，而下游
`isModelSelfNarration()` 正则专门在过滤这类自述——源头模板与下游过滤器在互相打架。现在源头写
「做出来的 / 文件 / 还差」，并明说不要用 blocker、不要抄系统提示原文。技能合同（SKILL.md）与
`seatbelt.ts` 的沙箱拒绝说明同步。这些是模型可见文本，走 `pnpm gen:expected`。

**改到的非词典文件，整份词典搬进 locale 文件，不做半迁移。** 门禁按「文件 + 归一化片段」记棘轮，
所以就地改一句话会同时产生「基线条目已消失」和「新增违规」。既然要动，就把该文件的词典整体搬进
`*-copy.ts` / `locales.ts`（新增 9 份），带插值的文案改走 `{name}` 占位符 + `routeTf/webTf/serviceTf`。
结果是 ui-i18n 棘轮基线**净减 815 条**、禁词基线净减 4 条，只删不加。

## Alternatives considered

**「保留 id 前 8 位，管理员用它对齐记录」**（原注释里的理由）：没选。管理员对齐记录靠的是时间与对象
名称，8 位十六进制既认不出是谁也拼不回全 id；真要取证，`data-*` 上的完整值比截断串有用得多。

**给 `labelFromMap` 的缺映射抛错**：没选。渲染路径上抛错等于一条脏枚举让整页白屏，代价远大于收益。
中性词 + 测试红是同样严格但不伤线上的做法。

**把洗词层整个删掉**：没选。`reasons`/`summary_md` 是模型写的自由文本，提示词只能约束、不能保证；
留一层最后兜底是对的，错的是让它长成 20 条没人知道来源的正则。

**服务层错误消息逐条双语化**：没做。这一层历史上没有 locale 参数，把 locale 一路传下去是另一件事；
`services/locales.ts` 先把中英两侧都写下来、调用点按原行为传 `"zh-CN"`，等有人接 locale 时直接可用。

**`apps/api` 复用 `packages/ui` 的 `structuredFieldLabel`**：不能——`apps/api` 不依赖 `@workhub/ui`。
在 `services/locales.ts` 里放了同一批字段标签，注释里互相指认，避免两处漂移时无人察觉。

## Consequences

**用户看得到的变化**：五种路由态、右栏、设置页、成本页、回放页、冲突卡、登录与邀请屏、升级与预算卡、
AI 融合交付文件的文字都变了。渲染结构没有动——只有文案与被删掉的三块（右栏「数据源」区块、
搜索/知识页的「运行时: 实时数据」指标、回放页的结果指纹行）。

**测试口径**：所有断言按新文案逐条更新，没有放宽成任意匹配。新增 4 处覆盖：枚举兜底登记簿、
洗词层 12 条规则、AI 融合交付文件的形状与文件名、提议摘要洗词与标题过滤。

**门禁**：ui-i18n 基线净减 815 条、禁词基线净减 4 条（只删不加）；模型可见的提示词按既有约定
加 `ui-i18n-allow` 而不是进基线。`pnpm gen:expected` 重生成 4 份基线，只有工作纪律四行变化，二次运行幂等。

**踩到的坑（值得记）**：`assert.ok(x.includes("…"))` 在 4000 行的大测试文件里失败时，node 会读源文件
并用 acorn 解析来生成「表达式为假」的错误消息——实测把整个测试文件挂死数分钟且**零输出**（node 的
测试运行器要等文件跑完才刷 TAP），看起来像死循环。改文案让这行失败时定位花了很久。这类文件里
一律写 `assert.equal(x.includes("…"), true)`。

**遗留**：`meeting-pages.ts` / `drive-pages.ts` / `work-item-comments.ts` / `risk-monitor.ts` /
`conversation-turns.ts` 里还有约 10 处「事项 / 工单」，不在本工位的改动范围内，留给下一轮按 §11 收口。

设置页的「工作进程数 / 消息服务 / 数据库 / 运行时」四行已经在「系统诊断（管理员关注；普通成员只读
参考）」分区里，这轮只把标签改成「并发处理能力 / 消息通道 / 数据存储 / 服务状态」。审查建议是普通成员
不渲染该分区——那是权限行为变更，不是文案改动，留给产品拍板。
