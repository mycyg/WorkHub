### 批 AVATAR · 头像与资料入口（2026-07-14 用户点名新增）

用户原话：群聊缺「用户自己配置头像」+「修改个人介绍等信息」的功能，且资料要 AI 可读作为派活依据。
事实核对：**资料编辑与 AI 消费已在 R13 批 A2 落地**（设置页「我的资料」= title/bio/技能标签，
GET/PATCH /me/profile，派活评分吃资料完整度+技能重合度）——本批补齐真正缺的**头像**，并顺手把资料
入口的发现性做足（与 ONBOARD 轻量先行项①合流）。

- 数据模型：`users` 加 `avatar_webp bytea`（nullable）+ `avatar_updated_at timestamptz`，迁移 `0054_user_avatar.sql`。
  **不引对象存储、不引图片处理依赖**（开源自托管友好）：客户端 canvas 降采样到 256×256 再上传，服务端只做
  magic bytes 校验（webp/png/jpeg）+ 256KB 硬顶，超限 413 人话报错。
- 端点：`PUT /me/avatar`（二进制 body）/ `DELETE /me/avatar`（回退首字母 tile）/ `GET /api/users/:id/avatar`
  （登录可见，同工作区；ETag=avatar_updated_at，304 缓存）。
- 渲染点：工作台聊天消息行、顶部成员条、建群选人器、设置页预览；**无头像回退现有首字母色块 tile 不变**
  （Cuu 的猫头像不受影响）。web 端渲染点=成员相关列表（如有）+设置预览，聊天归桌面。
- 上传 UI：web /settings「我的资料」卡加头像位；桌面 Spotlight 设置同款分区。图片选择用系统 file input，
  裁剪=居中方形 canvas，不引裁剪库。

### 批 CHAT · 聊天基础完整度

数据模型（均为 additive 迁移）：
- `conversation_messages` 加 `edited_at`、`deleted_at`（墓碑：删除后正文清空、渲染「此消息已删除」占位，不物理删，审计链保留）、`reply_to_message_id`（引用回复，自引/跨会话禁止）。
- 新表 `message_reactions(message_id, user_id, reaction_key)` 唯一约束三元组；reaction **用 emoji（用户拍板破例，2026-07-13）**，精选固定小集合起步（赞成/反对/完成/疑问/关注对应的常用 emoji），不开放全量 emoji picker（防治理失控），集合可后续扩。这是全项目无 emoji 纪律的唯一豁免点，其余 UI/文档纪律不变。
- **彩蛋（桌面端 stretch，不设验收门）**：emoji reaction 联动 Cuu 桌宠动画——当前会话里 Cuu 发的消息收到 reaction 时，桌宠播对应情绪动画（赞→开心、疑问→歪头之类）。技术上是顺路的：桌面端已有桌宠动画态机 + reaction 走 SSE 事件，消费点加一个「目标消息 sender 是 Cuu → 映射动画」的分支即可，纯桌面端增量、失败静默不影响聊天主链路。做不完不拖批次。
- 已读：新表或复用现有游标（施工时盘点 `conversation_participants` 是否已有 last_read_seq 类字段），群内显示「已读 N/M」聚合，不做逐人列表（隐私+噪音）。
- 在线状态（presence）：不落库，SSE 心跳内存态 + 定时衰减；头像点缀两态（在线/离线），typing indicator 已有不动。

规则红线：
- 编辑/删除只限本人消息、编辑限 15 分钟时窗、删除不限时（**用户已拍板，2026-07-13**）；Cuu 消息不可被人编辑；被引用的消息删除后引用侧显示墓碑。
- 编辑过的消息渲染「已编辑」标记；行动卡/工单等已从旧文本派生的下游**不回溯重算**（如实标注语义：派生物基于当时的原文）。
- 所有新事件走既有 SSE 契约扩展（照 zod 静默丢弃模式，旧客户端不炸）。
- P1-11 在 FIX 批修完后，本批的乐观 UI/失败重试补齐两端。

### 批 SEARCH · 全局搜索

- MVP 路线：**PG 原生，零新部署依赖**（开源自托管友好是硬约束）——`pg_trgm` GIN 索引做 CJK 子串匹配，覆盖：会话消息、网盘文档名+正文、工单标题+描述、会议纪要。不引 zhparser/pg_jieba（自托管装扩展的门槛劝退贡献者），不引外部搜索引擎。
- 统一端点 `GET /api/search?q=&scopes=`：逐 scope 各自 limit + 鉴权在 SQL 内逐 actor 收口（复用项目健康 DF-2 的教训，不做全局 cap 饿死）。
- 入口：聚焦盒新增「搜索全部」能力内联（现有意图分类扩一类）+ web 顶栏搜索页；结果分组渲染、点击直达（会话定位到消息 seq、网盘定位到文件、工单直达详情）。
- 语义检索（embedding）作为二期，等 MVP 用出真实痛点再立项，不在本批打包。

### 批 MEM · 记忆可见可治理

- 服务端：用户记忆 + 团队技能已有存储与夜间 curation，本批补**读写管理面**：列表/详情/编辑/删除/停用端点（PATCH 走受限编辑补丁模式，沿 K2 已有纪律）；每条记忆带出处（哪次会话/哪个 run 学到的，存储若缺出处字段则补 additive 迁移）。
- 前端：web 设置区「Cuu 的记忆」页 + 桌面 Spotlight 设置视图同款分区（落点在 R13 批 P3 的 AI 分区旁）；分「关于我」（用户记忆）与「团队技能」两 tab；删除需确认、显示「删除后 Cuu 将忘记这条」。
- 治理边界：团队技能的编辑权限=管理员，普通成员只读（**用户已拍板，2026-07-13**）。

### 批 FEEDBACK · AI 反馈闭环

- Cuu 文本回复、提议卡、行动卡上加「有用/没用」轻量反馈（字符 tile，不是 emoji）；落 `ai_feedback` 表（对象类型+对象 id+用户+判定+可选一句话）。
- 夜间 curation 消费：差评样本进技能蒸馏的反例池，好评强化；成本记账沿 K5 分账。
- 不做打分制/五星——二值+可选备注，降低反馈摩擦。

### 批 RISK · 风险预警巡检

- 新 worker：定时巡检（复用 scheduler 范式 + isConfigured 守卫），PM 视角三类信号：工单停滞 N 天、deadline 临近未动工、项目成本异常放量。
- 产出走既有主动汇报通道（会话内 Cuu 汇报消息 + 通知），限频合并（一天一次 digest 式，不逐条骚扰——这是批内固定策略，不是打扰预算升维）。
- 全部阈值进 settings 可配，默认保守。

### 批 GH · GitHub 集成（我的判断：做，理由=内部研发团队+开源社区双受益，Cuu 从自报进度升级为客观事实感知）

- 项目级绑定 repo（PAT/deploy key，服务端存储加密，桌面端零密钥纪律不变）；轮询为主（自托管无公网 webhook 也能用），webhook 可选加速。
- 信号消费：commit/PR/issue 动态进项目健康与 Cuu 巡检上下文；军团 run 产出若关联 PR，链接进提议卡。
- 明确不做：代码托管镜像、CI 状态面板、review 工具——只做「信号进感知」，不重造 GitHub。

### 批 PERF · 长会话性能
