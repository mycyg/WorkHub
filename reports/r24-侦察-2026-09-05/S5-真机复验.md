## 三、新发现

### N-01（P0，本轮引入的回归）三张登录门/连接屏渲进 720x64 的搜索条窗口，内容被裁到只剩标题

**证据**：`09-launch-with-api-main.png`（首启屏只露出 "Welcome to WorkHub" 一行）、
`10-connect-screen-clipped.png`（连接屏几乎全白，只见玻璃盒顶边）、
`46-zh-firstrun-clipped.png`（中文轮复现）、
`04-firstlaunch-main-after-scroll.png`（用滚轮盲滚才露出 "Sign in" 按钮）。
放大后内容本身完全正常：`06-firstrun-screen-resized-diagnostic.png` / `11-connect-screen-resized.png`。

**根因**：
- `apps/desktop-webview/src/browser.ts:306-317`——`desktopBootScreenForGate` 分出的
  `credential-gate` / `rebind` / `connect-server` 三条分支挂完 DOM 就 `return`，**早于聚焦盒控制器创建**。
- 全仓唯一的窗口尺寸同步是 `resizeDesktopMainWindow`
  （`apps/desktop-webview/src/desktop-window-controls.ts:31`），只被
  `browser.ts:202`（聚焦盒控制器的 `resize` 回调）和 `browser.ts:239` 用到——三张屏一次都没调。
- 主窗声明高度就是 64（`client-tauri/src-tauri/tauri.conf.json`，main window `"height": 64`）。

**影响**：全新安装的用户**看不见也点不到**登录表单。窗口 `resizable: true` 且能滚，所以不是死局，
但没有任何提示说"往下滚"。这是本轮首启屏改动（`3fc9bb96` / `2c00fd91` / `ec360d95`）引入的。

**修法**：三张屏挂载后按内容高度调一次 `resizeDesktopMainWindow`；内容变化时（切页签、
错误行出现、连接结果卡展开/收起）重测一次；离开这三张屏时恢复聚焦盒尺寸。
**量**：小（~30 行 + 单测）。**模型**：sonnet。

### N-02（P0）「连接到你的服务器」屏在真实路径上不可达；后端不可达时仍把用户扔进注定失败的昵称屏

**证据**：API 全关 + 全新安装 → `06-firstrun-screen-resized-diagnostic.png` 是昵称屏（"This device hasn't
connected to this server before — enter a nickname to get started."），提交后
`08-firstrun-signin-noapi-result.png`：`Sign-in failed — check the backend connection and retry.`，
整屏没有服务器地址输入框。连接屏只有人为往 localStorage 写锁才逼得出来（`11-connect-screen-resized.png`）。
设置页也没有服务器地址项（`32/33-settings-*.png` 已滚到底）。

**根因**：
- `apps/desktop-webview/src/desktop-login.ts:214-237`——`resolveDesktopFirstRunGate` 的返回类型就只有
  `"needs-credentials" | "logged-out"`；`probeDesktopAuthMode` 网络失败回 `null`
  （`desktop-login.ts:205-207`），而 `null` 在第 236 行被当成「按 nickname 处理」→ `"logged-out"`。
  「探不到 auth_mode 字段的老服务端」和「根本连不上」被合并成了同一个分支。
- `apps/desktop-webview/src/browser.ts:150-155` 拿到这两个值就直接 return，
  `gate === "offline"` 只可能来自 `desktop-login.ts:181` 的 `{kind:"busy"}`（跨窗锁 5 秒抢不到），
  而连接屏在 `browser.ts:316` 只认 `offline`。

**影响**：S3 的 B-01/B-02 修了 CSP 和这张屏本身，但**入口判定没修**——
「团队把服务器跑在别人机器上、我这台装了包」这条主场景，用户依然无处填地址。

**修法**：让 `probeDesktopAuthMode` 区分「探到了但不认识」与「不可达」（后者返回独立信号），
`resolveDesktopFirstRunGate` 在不可达时回 `offline`；另外在设置页补一条「服务器地址」入口，
不然登录之后再想换服务器同样无路。
**量**：中（判定链 + 设置页入口 + 单测）。**模型**：sonnet。

### N-03（P1）桌宠窗在本次会话内登录后永不复位，一直挂「去主窗口登录后 Cuu 才能帮你」+「离线」

**证据**：`41-pet-online.png`（英文轮：主窗已登录、项目已建、工作台显示 "Mei Zhang · connected"
之后 12 分钟，桌宠仍是 first-run 卡 + Offline）、`52-pet-after-signin-zh.png`（中文轮复现）。
重启应用后立刻恢复正常 260x340 常态（`58-pet-relaunch-with-token.png`）——所以是**本次会话内不复位**。

**根因**：桌宠 boot 在 `apps/desktop-webview/src/browser.ts:458-462` 一次性取 `signInNeededContext`
渲那张卡；主窗登录成功只 `window.location.reload()` 自己
（`browser.ts:213` 凭据门 / `browser.ts:228` 重绑屏）。跨窗广播里有 `workhub-logged-out`、
有 `workhub-server-changed`，唯独没有「登录成功」这一条。

**影响**：首次登录后 Cuu 全程装死，且桌宠窗一直撑在 520x720 挡住屏幕中部。
对「Cuu 为核心」的产品定位，这是首日体验的正面损伤。

**修法**：登录成功时照 `set_server_url` 的模式发一条跨窗广播，桌宠/工作台收到即 reload。
**量**：小（~20 行 + 单测）。**模型**：sonnet。

### N-04（P1）热态 `workhub://` 深链只把窗口拉回前台，不导航

**证据**：主窗停在 Notifications → Option+Space 隐藏 → `open workhub://open/settings`
→ 窗口回来，**仍在 Notifications**（`28-deeplink-settings-from-notifications.png`）；
`workhub://open/approvals` 同样（`29-*.png`）。对照：托盘「设置」同一时刻能打开设置页
（`31-tray-settings-result.png`，窗高 348 → 855）。

**已排除环境干扰**：本机 LaunchServices 里注册着 **10 份** 同 bundle id `com.mycyg.workhub` 的
WorkHub.app（旧 worktree、`.codex` 目录、5 个挂载过的 dmg 卷）。用
`lsregister -f <本轮 .app>` 钉死我这份、确认只有 1 个进程在跑，复测结论不变
（`59-deeplink-retest-after-lsregister.png`），随后 `lsregister -u` 注销了临时构建。

**判断**：`b463d96c` 修好的是「破坏性默认值」那一半（`spotlight-shell-navigation.ts:43-44` 现在
会忽略 `show-main`/`hide-main` 原因的事件，`:62` 认不出的路由也不再 `reset()`），
S3 的「盒子被洗成 idle」确实消失了；但导航这一半没通。托盘同走
`execute_window_control` 却可用，说明 `execute_window_control` 之后是通的，
问题在 macOS 热态 `on_open_url`（`client-tauri/src-tauri/src/main.rs:1845-1851`）
是否触发、或 `handle_deep_link_url` 生成的 payload 被过滤。壳层日志里没有
`deep_link_failed`（只有失败才打日志，所以不能反证）。

**修法**：先在 `handle_deep_link_url` 落地路径上加一条 `shell_log_info`（收到的 URL + 生成的 payload），
一次真机跑就能定位是「URL 没送达」还是「payload 被过滤」，再针对性修。
**量**：中（先定位再修）。**模型**：sonnet。
